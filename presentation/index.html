01 / 问题定义

我们到底要解决什么？

输入

目标根域名：qq.com

信息源：Bing / 百度公开搜索结果页。

查询语法：site:qq.com

输出

合法、去重、排序后的根域与子域名列表。

每条结果应保留可解释的来源，例如搜索结果卡片中的完整目标 URL。

关键约束

  • 不把搜索引擎中转链接当成目标。
  • 不把 evilqq.com 误认为子域名。
  • 遇到验证、限流或页面结构变化时记录现象。

不是本实验要做的事

  • 不访问搜索结果指向的网站。
  • 不做 DNS 存活验证。
  • 不处理验证码，也不尝试绕过。
02 / 起点

Bing 原脚本：一个清晰的最小闭环

# 1. 请求 site: 结果页
for page in range(pages):
    response = requests.get(
        "https://www.bing.com/search",
        params={
            "q": f"site:{target_domain}",
            "first": page * 10 + 1,
            "count": 10,
        },
        headers=headers, timeout=15,
    )
    response.raise_for_status()

# 2. 遍历标题链接并取 hostname
for result in soup.select("li.b_algo h2 a[href]"):
    hostname = (urlparse(result["href"]).hostname or "")
    hostname = hostname.lower().rstrip(".")

# 3. 严格域边界过滤 + Set 去重 + 排序
if hostname == target_domain or hostname.endswith(f".{target_domain}"):
    subdomains.add(hostname)
return sorted(subdomains)

它为什么适合作为起点？

  • 流程短：请求、解析、过滤、输出四步完成。
  • 分页明确：first = page * 10 + 1。
  • 边界正确：精确等于或严格以 .qq.com 结尾。
  • 数据结构合适：集合自然去重，排序方便复核。

可迁移的核心：不是某个搜索引擎的 CSS 选择器，而是“完整 URL → 规范化主机名 → 域边界校验 → Set → sorted”的数据处理链。

04 / 实验现象

普通 requests 为什么没有得到结果？

302
首次请求得到临时重定向，而不是正常搜索结果 HTML。
/captcha
Location 指向百度验证码页面，属于明确的停止信号。
0
本次 requests 路线未确认任何目标域名；零结果不等于不存在子域名。
# 搜索页不允许自动跟随到验证页
response = requests.get(
    search_url,
    allow_redirects=False,
    timeout=15,
)

location = response.headers.get("Location", "")
if response.status_code in (403, 429, 503) or "wappass.baidu.com" in location:
    logs.append("发现访问限制或验证提示，停止请求。")
    break

应该记录什么？

  • 请求 URL、HTTP 状态、页面标题、Location、Retry-After。
  • 停止位置和此前已收集的部分结果。
  • 页面结构变化、无结果节点、网络失败等可区分的状态。

可能差异来自哪里？

普通 HTTP 客户端和浏览器的会话状态、JavaScript 执行、请求特征与资源加载行为不同。仅修改 User-Agent 不能推导出相同结果。

05 / 转折

从“伪装请求”转向“复用现有浏览器页面”

已打开 Edge用户正常浏览，浏览器保有自己的会话状态。
browser-harness独立命令行工具，附着现有 Edge。
页面请求由 Edge 自行处理 Cookie、JS 与网络栈。
DOM 读取只读取已展示的搜索结果卡片与属性。
JSON 证据Python 保存结果、来源和状态。

这个方案做了什么

  • 普通脚本通过 stdin 调用 browser-harness.exe。
  • 由 Edge 加载百度结果页，结果页内运行少量 DOM 解析代码。
  • Python 只接收采集器 print() 的 JSON。

这个方案没有做什么

  • 不读取、复制或导出 Cookie、密码、Token、profile。
  • 不点击结果，不访问 qq.com 页面。
  • 验证页出现时只返回 verification_required_stop。
06 / 外层脚本

Python runner：负责附着、接收 JSON、保存证据

# run_current_page.py
# 1. 环境变量优先；未设置时从 PATH 查找 browser-harness
HARNESS = os.environ.get("BROWSER_HARNESS", "browser-harness")

def run_harness(command):
    process = subprocess.run(
        [HARNESS],             # 例如 D:\...\browser-harness.exe
        input=command,         # 把 collect_current_page.py 传到 stdin
        text=True, encoding="utf-8",
        capture_output=True, timeout=60,
    )
    if process.returncode != 0:
        raise RuntimeError(process.stderr + process.stdout)
    return json.loads(process.stdout)

# 2. 当前结果页入口
command = (SCRIPT_DIR / "collect_current_page.py").read_text(
    encoding="utf-8"
)
result = run_harness(command)
json_path, text_path = write_results(result)

HARNESS 从哪里来？

PowerShell 的 BROWSER_HARNESS 环境变量会被 Python 的 os.environ 读取。没有设置时，代码尝试从 PATH 查找名为 browser-harness 的命令。

为什么用标准输入？

browser-harness 接受一段命令文本。外层脚本读取内层采集器源码后，以 stdin 传入，避免 PowerShell 复杂引号转义。

为什么不使用 shell？

shell 是 cmd、PowerShell 等命令解释器。传入参数列表 [HARNESS] 时，Python 直接启动 exe；不使用 shell=True，就不会让命令字符串再被 shell 按引号、管道和特殊字符解释一次。

产物如何组织？

每次运行向 output/ 新建时间戳 JSON 与 TXT；源码、旧证据和 Git 历史都不会被覆盖。

返回值如何处理？

returncode == 0 表示工具正常结束；非 0 时抛出包含 stderr/stdout 的 RuntimeError。正常 stdout 应是一段 JSON，json.loads() 将它转为 Python 字典。

07 / 调用接口

collect_current_page.py：它如何真正进入 Edge 页面？

# 这整份文件经 stdin 交给 browser-harness
print(js(r'''(function () {
    // 这里开始已经是网页中的 JavaScript
    var page = new URL(location.href);
    var report = {
        page_url: page.href,
        page_title: document.title,
        status: "",
        records: [],
        domains: []
    };

    // ... 检查页面、解析卡片、校验域名 ...
    return JSON.stringify(report);
})()'''))

四个运行层次

  1. runner：读取该文件文本并传给 subprocess。
  2. browser-harness：解释 stdin 中的 Python 命令，提供 js() 和 wait()。
  3. js()：把括号内的 JavaScript 注入当前 Edge 页执行。
  4. print()：把 js() 返回的 JSON 字符串写到 stdout，runner 再用 json.loads() 解析。

关键点：这里的 js() 不是 Python 标准库函数；直接用 Python 运行 collect_current_page.py 会报错。它必须作为 browser-harness 的标准输入命令执行。

08 / 内层采集器

DOM 里如何定位“真实目标地址”？

// collect_current_page.py 内的页面 JavaScript
var card = anchor.closest(
    ".result, .result-op, .c-container"
);
var candidates = [["href", anchor.href]];

[anchor, card].forEach(function (node) {
    if (!node) return;
    ["mu", "data-landurl"].forEach(function (name) {
        candidates.push([name, node.getAttribute(name)]);
    });
});

// 第一个合法、且属于 qq.com 的完整 URL 才入库
for (var i = 0; i < candidates.length; i++) {
    var result = validate(candidates[i][1]);
    if (result) { record.hostname = result.hostname; break; }
}

来源优先级

  1. href：若本身已是目标 URL，直接使用。
  2. mu：百度结果卡片通常给出的完整目标地址。
  3. data-landurl / data-log.mu：兼容页面结构差异。

为什么保留 source？

JSON 记录每个域名来自哪个属性。页面更新后，可以回溯判断是解析器失效，还是搜索结果本身没有提供完整目标地址。

09 / 数据质量

URL 与域名校验：避免“看起来像”的误收集

验证链

  • 拒绝非 HTTP/HTTPS、空白、反斜线、控制字符。
  • 拒绝 URL 用户名/密码部分与非法端口。
  • 统一小写、IDNA 与结尾点；检查总长度和每个 DNS 标签。
  • 只接受 qq.com 或以 .qq.com 结尾的主机名。
  • 使用 Set 去重，再按字母顺序输出。
// 严格域边界，而不是字符串包含
if (host !== "qq.com" && !host.endsWith(".qq.com")) {
    return null;
}

// 这些不应被收集
evilqq.com           // 不以 .qq.com 结尾
qq.com.example.org   // qq.com 不是根域
https://@qq.com      // 含用户名语法
https://-bad.qq.com  // 非法 DNS 标签

// 这些可以进入结果
mail.qq.com
a.app.qq.com
qq.com
10 / 可运行入口

从“当前结果页”到“当前空白页自动搜索”

入口 A
run_current_page.py

前提：当前 Edge 已停留在 site:qq.com 的百度结果页。脚本只读取 DOM，不导航。

入口 B
run_search_from_blank_tab.py

前提：活动页是 about:blank、edge://newtab/ 或 Edge 默认新标签页。脚本复用这个页面后自动搜索。

保护条件
active_tab_not_blank

如果活动页不是明确允许的空白页，则不替换该页面，只保存状态。这样不会覆盖用户正在查看的内容。

# Windows 示例：先声明 browser-harness 路径
$env:BROWSER_HARNESS =
  'D:\MCP_Servers\browser-harness-conda\Scripts\browser-harness.exe'

# 当前结果页模式：直接把采集器文本交给工具
collector = (SCRIPT_DIR / "collect_current_page.py").read_text(encoding="utf-8")
result = run_harness(collector)

# 当前空白页模式：前缀负责判断、导航和等待
command = NAVIGATION_PREFIX + textwrap.indent(collector, "    ")
result = run_harness(command)

# 命令行实际运行入口
python scripts\browser_harness\run_search_from_blank_tab.py

一个容易误解的点

“浏览器没有弹验证码”不等于“已登录百度账号”。本实验复用的是浏览器已有页面环境，不对账号状态做推断，也不读取任何会话凭据。

12 / 方法对比

从失败中得到的工程判断

维度requests 直接请求现有 Edge + browser-harness
网页加载者Python HTTP 客户端已有 Edge 浏览器
本次实验观察302 / 验证页正常结果页
目标 URL尝试读取 mu 或有限百度跳转直接读取页面卡片的 mu 等完整属性
验证码策略记录并停止检测到验证页时记录并停止
适用价值代码最短，适合理解搜索解析流程更接近人工正常浏览，适合读取已显示 DOM

不要把失败隐藏掉

302、429、无结果节点都是有价值的实验状态。

不要把中转当目标

“能解析 URL”不等于“是真实目标资产”。

不要把一次成功泛化

一次正常结果页是观察，不是对服务行为的承诺。
